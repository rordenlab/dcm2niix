# Parser Gotchas Reference

Use this before changing DICOM tag descent, sequence handling, compression/transfer syntax, encapsulation, slice geometry, or vendor-private parsing.

## Sequence And Tag Descent

The sequence latches `sqDepth04000561`, `is00089092SQ`, `sqDepthIcon`, and `is00540016SQ` scope nested tags; first-hit and depth semantics are intentional. `isSQ()` is the implicit-VR sequence allowlist: adding a tag recurses, omitting a tag treats the sequence as opaque. The commented-out `kCodeMeaning` LOCALIZER detector is intentional because referenced-image inheritance false-positives; Siemens XA localizers use private `(0021,103F) kAutoAlignData`.

## Vendor Parsing

UIH MOSAIC bvecs prefer private `(0065,1037)` over standard `(0018,9089)` regardless of file order. Enhanced single-volume slice spacing fallback uses first/last IPP when spacing is absent and Siemens/GE/UIH `InStackPositionNumber` is gated out. The high-slice path must still finalize affine when `dim[3] > kMaxEPI3D`.

GE DWI direction: VascularCollapseFlag `(0043,1030)` is per image: 3/4/5 R/L, A/P, S/I; 9/10/11 oblique R/L, A/P, S/I; 14 T2; 15 combined (trace); 16 DTI; 43–46 direction 1–4. Series DFAX `(0021,105A)`: 0 none, 1 S/I, 2 A/P, 4 R/L, 7 ALL, 8 slice, 16 TENSOR, 64 3-in-1, 128 tetrahedral; sites may strip it. TENSOR fills `(0019,10BB-D)`; DFAX ALL (MR30) writes zeros (other modes unverified), so EPI flags 3/4/5 (non-EPI PC-MRA may reuse them for flow) get a synthesized world-LPS unit vector (`isBVecWorldCoordinates`, rotated by `siemensPhilipsCorrectBvecs`, propagated to the series' first image in `nii_saveDTI`); oblique flags stay zero (frame unconfirmed). Trace vs reference is decided per volume (`isGEADCvol`, the image's own `numberOfDiffusionDirectionGE == 0`), never series-wide: a series-wide flag dropped older-GE b=0 references (bval>0, zero vector). ALL mode writes `(0019,10E0)` = 0 even for T2, so flag 14 forces bval 0 at parse. Validated only on synthetic copies (local sibling `dcm_qa_ge_dwi`, unpublished: source data sharing unconfirmed). MR30 `(0020,1002)` ImagesInAcquisition counts every image; normally `(0021,104F)` overrides it. Only for GE software >= 30 with 104F absent (`isImagesInAcqGE`; older GE `(0020,1002)` counts slices) does `locationsInAcquisition == nConvert` suppress "images may be missing"; with 104F present that equality can be real missing slices.

UIH (issue1035): `(0018,9082)` EffectiveEchoTime holds EffectiveEchoSpacing in ms, so it must not overwrite TE (true TE is `(0018,0081)`). UIH `(0019,1028)` BandwidthPerPixelPhaseEncode is per *acquired* pixel (EES = 1/(BWPE × AcquisitionMatrixPE)), unlike Siemens where it is per *reconstructed* pixel; TotalReadoutTime stays EES × (ReconMatrixPE − 1), so with in-plane interpolation it exceeds the vendor's physical readout time, matching Siemens dcm_qa `INTERP` behavior.

Philips Dixon (issue 1038): Water/Fat/In/Out-of-phase all report `ComplexImageComponent=MAGNITUDE`; the type comes from ImageType tokens `_W_`/`_F_`/`_IP_`/`_OP_` (classic `0008,0008` or legacy per-frame `2005,140F`, stable 5.1–12.3; R12 `FrameType` long-form names are not parsed). Matching is ungated because classic `ImageType` precedes `Manufacturer`. `dixonType` must split in `isSameSet`, the `gradDynVol` tie test, and `isScaleOrTEVaries` (TSE Dixon shares one TE). In the `isKludgeIssue809` rewrite, `dimensionIndexValues[k]` for `k >= nDimIndxVal` is the previous frame's rewrite, not file data. R12 leaves the Effective Echo Time index 0 for every echo, so the sort keys on TE; `qsort` is unstable and ties scramble echoes/slices. `isRealIsPhaseMapHz` is sticky per file: the per-frame copy only relabels Real volumes, magnitude keeps the file value so BidsGuess files a B0 map's magnitude under `fmap`. PAR/REC `dti4D` is malloc'd, so `nii_readParRec` must set `dixonType`/`isRealIsPhaseMapHz` per volume (they index tables in `saveDcm2Nii`). Regression: `dcm_qa_dixon`.

Parametric Map (issue 1041, SOP `1.2.840.10008.5.1.4.1.1.30`): channels share positions and differ only by per-frame `RealWorldValueMappingSequence` `LUTLabel` (0040,9210). The frame is `pmFrame-1`, counted from `FrameContentSequence` (0020,9111), which precedes the mapping; do not key on `nSliceMM`, which skips frame 0 when IOP is per-frame. A shared-group label (`pmFrame == 0`), empty labels, and second mappings per frame are ignored. Channel and `TemporalPositionIndex` go to `TDCMdim.pmChannel`/`pmTime`, never straight into `dimIdx` (the Philips `isKludgeIssue809` rewrite owns `dimIdx[6..7]`; reading slot 7 as a channel split non-PM R11+ dynamics per volume and overflowed `pmLabel`). Only a committed split copies them into `dimIdx[7]`/`[6]` (assumed unused) for a channel-then-time sort and sets the shape from counts, `xyzDim[4] = nPMChannel * nTime` (TPI range) and `xyzDim[3] = frames / xyzDim[4]`, never from the pre-derived `xyzDim`: the stack-position, temporal, and segment heuristics above may already have split it (dividing again turned slices into volumes). Temporal maps give one 4D file per channel. The split requires: no `isKludgeIssue809`, uncompressed pixels (historical: compressed multi-frame ignored frame order, now fixed; relax once compressed PM fixtures exist), a `FrameContentSequence` per frame, exactly `nSlice` frames in every (channel, TPI) cell (`nCell`; catches unlabeled frames, TPI gaps, uneven channels or times, and labels merged by 16-char truncation), `nSlice == maxInStackPositionNumber` when stacks are present (several stacks stay unsplit), channels <= `kMaxPMChannel-1` (15), frames divisible by `nPMChannel * nTime`, and frames that will be sorted (`numDimensionIndexValues == numberOfFrames`). Otherwise `pmChannel` is zeroed and the file stays unsplit and unlabeled, as before. Implicit VR descends into (0040,9096) only when `isParametricMap` (a gate next to the `isSQ()` calls, deliberately not the shared allowlist, so Philips implicit-VR RWV slope/intercept parsing is unchanged); otherwise the label is never reached. `pmChannel` splits volumes like `dixonType` (`gradDynVol` tie test, `isScaleOrTEVaries`) and `nii_readParRec` must zero it. The label is the filename postfix (dropped by `--terse`, `%h`/`%H`, `%O`; not in the sidecar). highdicom's nested `ContributingEquipmentSequence` Manufacturer "Highdicom…" matches `HI` → Hitachi when the top-level vendor is unknown; Hitachi is outside the allow-list that stores per-frame `dcmDim` records, so these files take the issue 372 position-rank fallback, which never fills `dcmDim` TE/scale fields, hence `calloc`. Both paths must work. Regression: `dcm_qa_parametermap`.

## Compression / Encapsulation

`kCompressJP2K` is the JPEG2000 transfer syntax marker, not the runtime decode toggle; `compressFlag` is the runtime decode toggle; RLE is `kCompressRLE`. JPEG lossless C3 with multi-item offset table bypasses the generic `dti4D->offsetTable[]` loop. Multi-fragment single-frame encapsulation uses `reassembleEncapsulatedFragments()` and is admitted only when `numberOfFrames <= 1`.

Encapsulated multi-frame (one fragment per frame) is decoded frame by frame in `nii_loadImgXL` with a one-frame header, so the whole-image steps (scaling, `locationsInAcquisition` reshape, Dimension Index reorder `dti4D->sliceOrder`, per-frame `nii_iVaries`, sform) must run once afterwards on the full image via `nii_loadImgXLFinish`, never per frame: per frame the reorder is a no-op (4D came out slice/volume transposed, split series mixed frames) and per-frame scaling turns 16-bit frames into float. The C3 stack decoder must count all frames (dims 3-7), not `dim[3]`: 4D JPEG lossless decoded one volume and overran the buffer. Regression: `dcm_qa_enh_compressed`. `nii_loadImgRLE` always writes interleaved samples, so RLE RGB converts to planar with `isPlanarRGB = false` regardless of PlanarConfiguration.

SOF3 component id `Ci` may be any 0..255 (T.81 B.2.2): GDCM lossless RGB writes 82/71/66 ('R','G','B'), DCMTK 0/1/2. `read_frame_header` stores components by position and planes match scans by `Ci`; indexing by `Ci` was a heap overflow that optimized builds often survive (issue 1054). `dti4D->offsetTable` holds the offsets of the last file parsed, so the generic per-frame loop in `nii_loadImgXL` walks the decoded file's own `(FFFE,E000)` items; using the table dropped earlier files of multi-file enhanced series (XA field map e1/e2, ASL) compressed as RLE, JPEG-LS, J2K or baseline JPEG. nanojpeg decodes Extended JPEG (`.4.51`, SOF1) including 12-bit grayscale (16-bit DQT, 64-bit IDCT passes: 32-bit overflows); TurboJPEG builds still reject 12-bit. C3 multi-frame with several fragments per frame (`dcmcjpeg +fs`) is reassembled and split at SOI (`FF D8` cannot occur in entropy-coded data) only when items outnumber frames; other codecs still reject that layout. Regression for all four: `dcm_validate/dcm_qa_jpg` (also run an ASan build).

## Geometry

UIH MRS IOP encodes direction times voxel size; only UIH branches may normalize these non-unit rows. The 3D PhaseEncodingDirection gate intentionally keeps `!SE` to avoid SPACE/FLAIR regressions (issue849) while allowing 3D EPI/GRE (and detected EPI where ETL is unset — see `bandwidthPerPixelPhaseEncode` gate, issue 1024). Derived-image warning suppression is deliberate — one diagnostic, not a cascade: the slice-direction and "missing 0020,0037" orientation warnings stay silent for derived / non-spatial images (e.g. Siemens color-FA).
